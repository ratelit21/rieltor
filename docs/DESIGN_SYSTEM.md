# Риелтор / визуальная система

## Цель
Спокойная архитектурная эстетика: выразительный первый экран, контролируемая смена тёплых и тёмных поверхностей, ясная типографика, немного шампанского. Это НЕ монохромный зелёный сайт и НЕ череда случайных цветных секций.

## Цветовые роли (единственный источник — `app/globals.css :root`)

| Роль | CSS token | Значение | Использование |
|---|---|---|---|
| Основной тёмный нейтрал | `--canvas` | `#1D2421` | общий холст/навигация |
| Акцентный лесной | `--forest` | `#21382F` | hero, выбранный фильтр, секции действия |
| Редакционный графит | `--warm-graphite` | `#2D302D` | скролл-история, тёмные карточки |
| Тёплый камень | `--warm-stone` | `#CBC0B0` | каталог, личное обращение, контрастные информационные зоны |
| Тёплая бумага | `--sand` | `#E7DFD2` | подложка чертежей; не заливать ею весь сайт |
| Основной тёмный текст | `--ink` | `#242A26` | каменная поверхность |
| Светлый текст | `--ivory` | `#F2EDE4` | графит и лесной |
| Шампанский | `--champagne` | `#D7BC97` | небольшие акценты, ссылки, заголовки на тёмном |
| Нейтральный вторичный текст | `--muted` | `#C7C4BA` | вспомогательные тексты на тёмном |

Цвета строятся на насыщенно-зелёной доминанте с нейтральными, слегка тёплыми поверхностями и ограниченным количеством шампанских акцентов. Не добавлять новые зелёные, золотые или коричневые цвета в отдельных компонентах без изменения общих токенов.

## Важные ограничения

- Уважать требования WCAG 2.2: обычный текст 4.5:1, крупный 3:1; на светлом камне использовать `--ink`, а не шампанский.
- Шрифты интерфейса минимум 15–16 px; избегать жирных микроподписей и `text-transform: uppercase` ради «премиальности».
- Навигация и стрелки — компоненты SVG из `lucide-react` (`Menu`, `X`, `ArrowUpRight`, `ArrowDown`). Не добавлять emoji или символ `↗` как замену иконке.
- Сохранять общую высоту кнопок, расстояние между текстом и иконкой, центровку через flex и `align-items: center`.
- Скролл-сцена показывает планировку **без scale pop**: чертёж расположен на собственной каменной сцене, меняется только opacity. Размер плана не должен быть маленьким модальным окном.
- При быстрой прокрутке использовать синхронизацию с реальным положением в документе. Не опираться только на последовательность независимых `onEnter`.
- Сохранять существующие маршруты, работу каталога, демо-форму и GitHub Pages export.

## Чеклист до слияния в main

1. `npm ci && npm run build` — успешно.
2. В Chrome проверить 390, 768, 1440 px без горизонтального переполнения.
3. Визуально сравнить главную, каталог, карточку и форму на одинаковом разрешении.
4. Проверить мобильное меню и фильтры; стрелки отрисованы как SVG и находятся на линии текста.
5. Резко перейти к эпизоду 02 и дальше к 03; чертёж появляется мягко, в доступном кадре, без наложения после ухода.
6. Не объединять PR в `main`, если хотя бы один проверяемый пункт не выполнен.
